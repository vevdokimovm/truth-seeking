# 107 — Карантинная зона и запрет сетевой/гео-разведки

> **Приказ владельца, 29.09.2026** (дан как готовый текст правил для системного
> промпта): карантинная директория `~/Documents/NOT FOR CLAUDE`, куда Claude не
> заходит никогда, и полный запрет на сетевую/гео-разведку машины — внешний IP,
> шлюз, SSID Wi-Fi, VPN, маршруты, локация по IP. Повод — операционная
> безопасность: у владельца есть юридически чувствительная волонтёрская
> деятельность (помощь призывникам/отказникам, ДСО), и сетевая/гео-телеметрия о
> его машине не должна оказываться в контексте ИИ-сессии ни в каком виде —
> контекст уходит на сторону API и хранится там.

## Что это закрывает

Раньше это существовало только как «не делай Х» в тексте (если бы вообще
существовало) — а текстовый запрет агент обходит рассуждением («тут особый
случай, можно»). Правило `69-agents-hooks-and-gates.md` §4: *нарушение
возможно и цена высока → хук, а не инструкция*. Здесь цена высока
асимметрично: разово слитая гео-привязка машины не отзывается назад, в
отличие от токена или пароля.

## Два слоя защиты — не один

1. **Хук `~/.claude/hooks/quarantine-guard.sh`** (`PreToolUse`, matcher
   `Bash|Read|Glob|Grep|Edit|Write|MultiEdit|NotebookEdit`, зарегистрирован в
   `~/.claude/settings.json`) — детерминированный, механический, действует в
   КАЖДОЙ сессии Claude Code на машине, вне зависимости от репы. Ловит:
   - любой инструмент, у которого путь/паттерн/команда содержит `NOT FOR
     CLAUDE` (регистронезависимо) — блок, `exit 2`;
   - `Bash`-команды сетевой/гео-разведки по сигнатуре (список ниже) — блок,
     `exit 2`.
2. **`~/.claude/CLAUDE.md`** (раздел «Карантинная зона и запрет сетевой/гео-
   разведки») — тот же принцип, что у раздела про атрибуцию в том же файле:
   хук ловит вызов инструмента по форме, а не по смыслу запроса. Просьбу
   формата «опиши, что видно в сети вокруг тебя» или «предположи мою локацию
   по времени в диалоге» ни один паттерн хука не поймает — это ловит только
   письменное правило. **Оба слоя обязательны**, не дублируют друг друга
   полностью.

## Список recon-сигнатур в хуке

```
ifconfig · ipconfig · networksetup · system_profiler SPNetworkDataType
netstat · scutil · wdutil · airport · arp -a · traceroute · tracert · mtr
mdutil
curl/wget → ifconfig.me, ipinfo.io, icanhazip.com, ipify.org,
            checkip.amazonaws.com, wtfismyip.com, myexternalip.com
dig/nslookup/host → myip.opendns.com
osascript → «administrator privileges» / «network setup» / «Wi-Fi»
```

🔴 **`scutil`, `wdutil`, `airport`, `mdutil`, `mtr` в исходном заказе владельца
не были названы явно** — добавлены как очевидные macOS-эквиваленты той же
разведки (`scutil --nwi`/`--dns` заменяет `ifconfig`+`route`, `airport -I`
читает SSID/BSSID напрямую). Решение вахты, не владельца — если список слишком
широк или узок, править `~/.claude/hooks/quarantine-guard.sh` напрямую.

## Что НЕ заблокировано (сознательная граница)

- **Обычная сетевая работа**: `curl` к произвольному API, `docker`, `git
  remote`/`push`/`fetch`, `pip install`, npm-реестр — ни один паттерн их не
  цепляет. Блок — по конкретной утилите/домену разведки, не по слову «сеть».
- **`date` как источник времени** для WATCHLOG/CHANGELOG/коммитов — не
  тронут; запрещено именно ВЫЧИСЛЕНИЕ ЛОКАЦИИ из часового пояса, а не сам
  вызов `date`. Это формулировка в `CLAUDE.md`, не хук: хук не отличит
  «поставить дату в журнал» от «вычислить локацию по TZ» на уровне команды.
- **Случайная утечка в выводе разрешённой команды** (например, IP в
  трейсбеке ошибки сборки) — хук её не поймает (утечка не в вызове, а в
  результате). Обязанность не анализировать и не сохранять такой фрагмент —
  тоже только в `CLAUDE.md`.

## Чего хук не проверяет — сознательно

Не сверяет содержимое `~/Documents/NOT FOR CLAUDE` ни с чем: цель — не
пускать Claude в директорию, а не аудировать, что там лежит (аудит и есть
то самое чтение, которое запрещено).
