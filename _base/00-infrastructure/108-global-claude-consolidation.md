# 108 — Консолидация `.claude/` в одно глобальное место

> **Приказ владельца, 29–30.09.2026, дословно:** *«каждый раз при запуске
> клода в любой из реп системы он считывает один файл настроек CLAUDE?
> иначе смысл инвариантность теряется. надо чтобы это всё было в одном
> месте и один файл для ВСЕЙ СИСТЕМЫ точно также как мы делали со скилами
> агентами»* — и следом: *«восстанови да все хуки механизмы и тд для
> системы»*.

## Повод

В этой же сессии `~/repos/base-repo/.claude/` целиком пропала с диска
(не через git — см. `00-CLAUDE-STOP.md` «Третье»). Восстановление
командой `git restore .claude` вернуло файлы, но не решило корневую
проблему: **даже целые, эти файлы работали только внутри base-repo.**

## Что было неправильно понято раньше

`.claude/skills/`, `.claude/agents/`, `.claude/hooks/`, `.claude/settings.json`
лежали ТОЛЬКО в `base-repo/.claude/` — то есть Claude Code видел их только
в сессиях, открытых именно в base-repo. Остальные 65+ реп, унаследовавших
те же правила текстом (`WATCHLOG`, `CHANGELOG`, `_base/`-зеркало), не
получали ни одного из мехнизмов, которые эти правила должны были
принудительно исполнять. Замер, уже лежавший в базе и не увиденный вовремя
(`97-claude-code-capabilities.md` §6, 30.08.2026): *«из 62 реп скиллы
видны в 2»* — раздача клала копии в `_base/.claude/skills/`, а Claude Code
ищет их в `.claude/skills/`, на уровень выше. Путаница усугублялась
недостроенным плагином `~/.claude/skills/base-kit` (симлинк на
`.claude/plugin/`) — каталог `.claude/plugin/` содержал только манифест,
без `skills/`/`agents/`/`hooks/` внутри, то есть был пуст по факту.

## Проверено и отвергнуто: локальный плагин

Запрошено у `claude-code-guide` (30.09.2026): корректная раскладка
плагина — `<корень>/skills/`, `<корень>/agents/`, `<корень>/hooks/hooks.json`
как соседи `.claude-plugin/plugin.json`; хуки плагина живут в отдельном
`hooks/hooks.json`, не в `plugin.json`. Симлинк как способ установки
плагина **не документирован как поддерживаемый**. При этом официально
подтверждено и проще: `~/.claude/skills/<имя>/SKILL.md` и
`~/.claude/agents/<имя>.md` видны **всегда, в любом проекте** — без
плагина, без маркетплейса, без манифеста. Решение — не достраивать
плагин, а синковать напрямую.

## Архитектура: канон в git, активная копия — глобальная

```
base-repo/.claude/{skills,agents,hooks}/   ← канон, правится здесь, в git
              │
              │  scripts/sync_global_claude.py
              ▼
~/.claude/{skills,agents}/                 ← копия, видна ВСЕГДА и ВЕЗДЕ
~/.claude/settings.json → hooks            ← регистрация хуков, тоже глобальная
```

- **Почему копия, а не симлинк каталога целиком.** `~/.claude/skills/` —
  общее пространство: там же живут синкнутые системные скиллы Anthropic
  (`pdf`, `docx`, `skill-creator` и т.д.) и другие плагины. Один симлинк
  на весь `~/.claude/skills/` его бы уничтожил; симлинк на подкаталог
  плагина не сработал по структурной причине выше. Копия, которую
  пересобирает скрипт, — тот же принцип, что уже стоит на всей системе
  (`_base/`-зеркало из `sync-base.sh`), только для того единственного
  каталога, который Claude Code реально читает автоматически.
- **Почему это не возвращает риск «физической потери без git».** Канон
  остаётся в base-repo под git. Если `~/.claude/{skills,agents,hooks}`
  снова физически пропадёт — `python3 scripts/sync_global_claude.py`
  восстанавливает всё за секунды, без `git restore` и без риска потерять
  несохранённое (глобальная копия ничего своего не хранит, только зеркалит).

## `scripts/sync_global_claude.py`

Копирует `.claude/skills/` и `.claude/agents/` в `~/.claude/` (перезапись
файлов), копирует `.claude/hooks/*.sh` с сохранением `+x`, дописывает в
`~/.claude/settings.json` → `hooks` недостающие регистрации (идемпотентно —
сверяет по тексту команды, не дублирует при повторном запуске).
`--check` — только сверка, код возврата ненулевой при расхождении, ничего
не пишет.

**Не удаляет** из `~/.claude/skills|agents/` то, чего больше нет в
base-repo (namespace общий с чужими плагинами — слепое удаление задело
бы их). Если скилл/агент выводится из базы — убрать его из
`~/.claude/skills/<имя>/` вручную тем же ходом.

## Что стало глобальным (4 хука + 18 скиллов + 7 файлов агентов)

| Хук | Событие | Была видна только в | Стала видна |
|---|---|---|---|
| `protect-base-mirror.sh` | `PreToolUse` (Edit/Write/MultiEdit) | base-repo (где `_base/` и не бывает) | везде, где есть `_base/` — то есть теперь реально работает |
| `ritual-gate.sh` | `Stop` | base-repo | везде — с фиксом ниже |
| `task-hygiene.sh` | `Stop` | base-repo | везде (уже была написана репо-агностично, от `$CLAUDE_PROJECT_DIR`) |
| `watch-identity.sh` | `SessionStart` | base-repo (несмотря на то, что сама уже искала реестр по абсолютному пути для чужих реп — `84-claude-accounts.md`) | везде |

### 🔴 Правка `ritual-gate.sh` перед глобализацией — было бы неверно для 65 реп из 66

Хук сверял архив/тег с именем **`base-repo`**, зашитым строкой (в архиве
`base-repo-v${version}.zip` и в `https://github.com/vevdokimovm/base-repo.git`).
Глобально это сверяло бы АРХИВ ЛЮБОЙ РЕПЫ с ГИТХАБОМ base-repo — то есть
хук всегда находил бы чужой тег и либо ложно блокировал, либо ложно
пропускал. Исправлено: имя репы и remote берутся из `$CLAUDE_PROJECT_DIR`
(`basename` абсолютного пути + `git remote get-url origin`, с запасным
шаблоном `github.com/vevdokimovm/<имя-репы>.git`, если `origin` не задан).

Проверено живьём (30.09.2026): `ritual-gate.sh` из глобального пути,
запущенный с `CLAUDE_PROJECT_DIR=<base-repo>`, корректно нашёл `VERSION`,
прогнал `revision_check.py` и `deploy_version_gate.py` (оба гейта
существуют только в base-repo — остальные репы их не имеют, и хук это
переживает: каждая проверка обёрнута в `[ -f ... ]`, в чужой репе просто
не сработает, а не упадёт) и корректно составил имя архива под текущую репу.

## Что осталось локальным в base-repo/.claude/

`settings.json` — теперь пустая заглушка с комментарием-указателем (не
дублирует регистрацию хуков — иначе в сессии base-repo каждый хук
исполнялся бы дважды). `settings.local.json` — разрешение, специфичное
для этой репы, не переносится. Сами файлы скиллов/агентов/хуков остаются
здесь — это канон, `~/.claude/` — только их зеркало.
