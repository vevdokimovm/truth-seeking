**Повод.** Заказ владельца 29.09.2026: перенести стандарт README в реестр
стандартов. Основание для переноса — то же, по которому реестр вообще
существует: правило уже нарушалось с последствиями. Док `98` написан
29.08.2026, и за месяц его нормы нарушались **систематически** — README
описывал прошлое состояние при поднятой версии (ровно тот класс, ради
которого заведён `readme_status_gate.py`), а разделы «выглядят как содержание
и им не являются» ловились вахтой поимённо, а не проверкой.

🔴 **Разница, ради которой перенос и делается.** Док отвечает на вопрос
«как устроен хороший README и почему именно так». Стандарт отвечает на другой:
**что обязано быть, и чем это проверяется**. Пока правило жило только доком,
его соблюдение держалось на том, что вахта вспомнила его прочитать.

## 2. Область

Применяется к **корневому `README.md` каждой репы системы**, включая
`base-repo`.

**Не применяется** к `README.md` подкаталогов (`reports/*/README.md`,
`00-infrastructure/README.md` и подобным): это навигаторы раздела, их предмет
и объём задаёт `75-readme-status-block.md` §5б, а не этот стандарт. Смешение
этих двух вещей — частая ошибка: файл называется одинаково, а жанр разный.

## 3. Термины

**Класс репы** — значение из `.repo-class`: `product` · `infra` · `core` ·
`satellite`. Класс определяет, какие разделы обязательны сверх общего скелета.

**Раздел-пустышка** — заголовок, под которым нет содержания либо содержание
не отвечает на вопрос заголовка («`## Структура`» со строкой «1 заметка»).
🔴 Считается **дефектом, а не недоделкой**: пустое место видно, а пустышка
выглядит ответом и потому не ищется.

**Утверждение о состоянии** — любое число или факт о репе в прозе README
(сколько файлов, сколько реп, какая версия, что сделано).

## 5. Порядок

README приводится в соответствие **не отдельной задачей, а шагом ритуала
батча** — иначе он отстаёт от репы, что и происходило весь сентябрь:

1. `rebuild_readme.py` — перестроить машинные части (структура, «Что это и зачем»).
2. Дописать человеческие разделы, если менялась граница репы или точка входа.
3. `bump_repo.py` — версия и блок статуса.
4. `readme_status_gate.py` и `revision_check.py` — до коммита, не после.

## 6. Запреты

1. **Копировать README продукта в репу-базу знаний.** У `chess` нет API,
   у `philosophy` нет быстрого старта; заголовок без содержания — нарушение
   СТ-004.6.
2. **Заводить раздел «на вырост».** Раздел появляется вместе с содержанием.
3. **Сочинять «зачем» за репу.** Где смысл не выведен — пишется, что не выведен.
4. **Ставить что-либо ниже подписи.** Читатель уходит после контактов;
   всё, что ниже, не существует.
5. **Править число в прозе, не сверив его с диском.** Число в README —
   обязательство перед гейтом, а не украшение.

## 7. Отступления

Журнал решений владельца, разрешивших отойти от нормы. Пока пуст.

🔴 **Известная слабость самого стандарта, названная при введении:** нормы
СТ-004.4, .5, .6, .8, .10 проверяются только вручную. Это ровно те нормы,
которые нарушались чаще всего, — и по устройству системы (`ARCH-001`,
`reports/architecture-defects.md`) правило без исполнителя есть обещание.
Норма СТ-004.10 автоматизирована быть не может по существу; остальные четыре —
кандидаты в гейт, и это записано как долг, а не как данность.
