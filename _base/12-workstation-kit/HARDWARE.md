## §0. 🔴 Что здесь можно держать, а что нельзя

### Износ — и два числа, которые нельзя путать

| | 02.09.2026 | 30.09.2026 | Что означает |
|---|---:|---:|---|
| **Percentage Used** | 108 % | **112 %** | доля израсходованной **гарантии записи**. Может расти выше 100 % — это пробег, не отказ |
| **Available Spare** | 100 % | **100 %** | доля **нетронутых резервных блоков**. 🔴 Вот это предвестник отказа — порог 99 % |
| Записано всего | 956 ТБ | **989 ТБ** | на диск 256 ГБ — каждая ячейка переписана ≈3 900 раз |
| Прочитано | — | 1.06 ПБ | — |
| Часов работы | 7 058 | **7 300** | накоплено за семь лет, не подряд |
| Включений | 528 | 533 | — |
| Аварийных выключений | 212 | **217** | +5 за 28 дней — машина гаснет жёстко (см. `reports/2026-09-06-night-shutdown.md`) |

**Темп записи по ряду из двух замеров:** 33 ТБ за 28 дней = **1.18 ТБ в сутки**,
то есть ≈136 ГБ на час работы. Норма бытовой работы — 1–3 ГБ/ч. Превышение
примерно **в 50 раз**, и причина названа в разборе от 02.09: своп при 8 ГБ.

🟡 **Вердикт:** диск в фазе, где **отказ приходит внезапно**. Пока
`Available Spare` = 100 %, ни одна ячейка не вышла из строя, и в таком
состоянии диски живут годами. Но когда резерв начнёт падать, он сыплется
за недели — предупреждения не будет.

### Место на диске — деградировало за месяц

| | 02.09.2026 | 30.09.2026 |
|---|---:|---:|
| Свободно | 97 ГБ | **35 ГБ** |
| Занято тома APFS | — | 84.8 % |

🔴 **Это прямо ускоряет износ.** SSD выравнивает запись по свободным ячейкам:
чем меньше свободного места, тем чаще переписываются одни и те же. Порог
из разбора — держать свободными 15–20 %; сейчас 15.2 %, то есть на самой
границе. Минус 62 ГБ за месяц — отдельный вопрос, куда они ушли
(`bin/disk_audit.py`).

## §4. Память в работе: своп как источник записи

Замер 30.09.2026, 10:42, аптайм 5 суток:

| Параметр | Значение | Оценка |
|---|---|---|
| Своп занят | **7.58 ГБ из 8.00 ГБ** | 🔴 своп почти исчерпан |
| Вытеснений страниц (pageouts) | **4 444 174** | 🔴 каждое — запись на диск |
| Свободной памяти | 58 % по `memory_pressure` | 🟡 мгновенное значение, обманчиво |
| Load average | 7.72 / 16.41 / **25.20** | 🔴 при 8 потоках: очередь втрое длиннее машины |
| Лимит частоты ЦП | `CPU_Speed_Limit = 73` | 🟡 процессор срезан до 73 % под нагрузкой |
| Термические предупреждения | не записано ни одного | 🟢 |

> **Связь прямая и она объясняет §3:** памяти нет → macOS вытесняет страницы
> на диск → 4.4 млн вытеснений превращаются в терабайты записи. Своп нельзя
> отключить: без него система убивает процессы вместо вытеснения.

## §7. Что из этого следует для работы с ИИ локально

Раздел заведён потому, что вопрос владельца 30.09.2026 — «работать без Клода,
локальной моделью» — решается не софтом, а вот этими числами.

| Требование локальной модели | Что есть здесь |
|---|---|
| много памяти под веса | 6.5 ГБ доступно из 8, и своп уже исчерпан |
| ускоритель (Neural Engine / CUDA / Metal-унифицированная память) | нет: Iris 655 для вывода бесполезна, MLX — только Apple Silicon |
| запас на диске под веса | 35 ГБ, на границе порога |
| ресурс диска на запись | выработан на 112 %, а вывод модели свопит |

🔴 **Вывод без смягчения: модели уровня Sonnet на этой машине не будет.**
Помещаются модели 3–4 млрд параметров в квантовании Q4 (≈2.5 ГБ), и работать
они будут на процессоре, единицы токенов в секунду. Это уровень черновика
и разметки, не уровень рассуждения. Подробный разбор вариантов — отдельным
документом по заказу того же дня.

## §8. 🔴 Бэкапа по-прежнему нет — проверено 30.09.2026

```
tmutil destinationinfo  →  «NO NAME», Kind: Local
tmutil listbackups      →  No machine directory found for host
```

Ни одной копии. Решение владельца от 02.09.2026 — **отложено сознательно**,
риск принят. Здесь это повторяется только числом, потому что за месяц
обстановка ухудшилась: износ 108 → 112 %, свободного места 97 → 35 ГБ,
аварийных выключений +5.

| Факт | Следствие |
|---|---|
| SSD выработал 112 % ресурса и **распаян** | заменить нельзя, только плату целиком |
| Копий ноль | восстанавливать неоткуда |
| 70 репозиториев уезжают релизами на GitHub | 🟡 уцелеет **система реп**, а не машина: всё вне реп не уезжает никуда |

## §10. Протокол повторного замера

Замер повторяется **раз в месяц** и при любом из событий: диск заполнился
ниже 15 %, `Available Spare` сдвинулся с 100 %, машина погасла аварийно,
появилось термическое предупреждение.

| Что | Команда |
|---|---|
| **ряд и производные** | `python3 12-workstation-kit/bin/hw_series.py` — дописывает строку в [`observations/hw-series.tsv`](observations/hw-series.tsv) и считает, что изнашивается быстрее всего |
| весь срез сразу | `python3 12-workstation-kit/bin/machine_probe.py` |
| прошивки и версии железа | `python3 12-workstation-kit/bin/firmware_probe.py` |
| износ SSD | `smartctl -a /dev/disk0` |
| батарея | `ioreg -rn AppleSmartBattery` · `system_profiler SPPowerDataType` |
| память и своп | `vm_stat` · `sysctl vm.swapusage` |
| лимит частоты и термика | `pmset -g therm` |
| место на диске | `df -h /` · `diskutil apfs list` |
| копии Time Machine | `tmutil destinationinfo` · `tmutil listbackups` |

🔴 **Новый замер не переписывает старый столбец, а добавляет свой.** Ценность
этого документа — в ряде: одна точка говорит «износ 112 %», две точки говорят
«плюс 33 ТБ за 28 дней», и только второе позволяет что-то предсказать.

**Сети в этом протоколе нет намеренно** — внешний адрес, шлюз, имя Wi-Fi,
статус туннеля не собираются ни при каком поводе
(`00-infrastructure/107-network-quarantine-and-recon-block.md`).
