# `local-brain` — локальная модель как исполнитель системы

> **Заведено 30.09.2026** по заказу владельца: работать с системой, когда
> платной подписки нет. Повод и разбор — [`ARCH-006`](../../reports/architecture-defects.md).

---

## §1. Что здесь лежит

| Файл | Что делает |
|---|---|
| [`Modelfile`](Modelfile) | «своя модель» в терминах Ollama: открытая база + системный промпт со сводом правил системы, параметры под 8 ГБ памяти. Сборка: `ollama create base-local -f Modelfile` |
| [`bench.py`](bench.py) | стенд сравнения моделей **на задачах этой системы**, а не на общих бенчмарках. Шесть задач, у каждой машинный грейдер |
| `bench-results.tsv` | append-only результаты прогонов: балл, секунды, ток/с по каждой задаче |

## §2. 🔴 Три вещи, которые путают, и их надо развести сразу

1. **Обучить модель с нуза нельзя** — порядок затрат миллионы GPU-часов.
   Речи об этом не идёт вовсе.
2. **`Modelfile` — это не обучение.** Это конфигурация поверх готовых весов:
   системный промпт, температура, контекст, шаблон. Модель начинает вести себя
   по своду правил владельца — и остаётся ровно такой же умной, как была.
3. **Дообучение (LoRA) учит СТИЛЮ и ФОРМАТУ, а не мышлению.** Дообученная 4B
   будет писать в конвенциях базы и не станет сильнее в рассуждении. Путать
   эти две вещи — значит ждать от дообучения того, чего оно не даёт.

## §3. Почему стенд свой, а не готовый бенчмарк

MMLU и SWE-bench отвечают «умна ли модель вообще». Нужен другой вопрос:
**справится ли она с работой, которая в этой системе реально делается**.
Поэтому шесть задач сняты с живых операций:

| Задача | Что проверяет | Почему именно это |
|---|---|---|
| `схема` | извлечение по JSON-схеме | основа разметки реестров |
| `числа` | сжатие с сохранением всех чисел | главный риск при сжатии тома в тезис |
| `класс` | классификация по закрытому списку | разметка карточек `PIT`/`ARCH` |
| `коммит` | Conventional Commits + запрет упоминать ассистента | железное правило атрибуции |
| `запрет` | отказ от сетевой разведки под давлением | запрет `107`, абсолютный |
| `незнание` | 🔴 сказать «не знаю» вместо выдуманного числа | **вес двойной, см. ниже** |

🔴 **Шестая задача важнее первых пяти вместе.** Слабая модель опасна не тем,
что ошибается, а тем, что ошибается **молча и уверенно**. Выдуманное число,
попавшее в базу знаний, потом считается правдой и расходится по ссылкам;
пустой ответ стоит паузы. Цены несопоставимы, поэтому и вес двойной.

## §4. Как слабая модель становится полезной

Не «заменить мозг», а **сузить задачу до проверяемой**. В этой системе
45 машинных проверок и 122 инструмента — то есть есть кому ловить ошибку
исполнителя. Схема рабочая:

```
узкий шаг с проверяемым выходом  →  гейт проверяет выход  →  провал виден сразу
```

Там, где выход проверить нечем (суждение «это дубликат?», «что поднять
в свод»), слабая модель не применяется вовсе — не из осторожности, а потому
что её ошибку там никто не поймает.

## §5. 🔴 Чего стенд не мерит — и почему число само по себе не вердикт

- **длинный контекст:** промпты стенда короткие, до 400 токенов. Работа
  с базой требует десятков тысяч, и деградация там другого порядка;
- **цепочки вызовов инструментов:** в стенде один ход. По независимому BFCL v4
  малые модели дают 0,4–36 % против 73 % у Sonnet 4.5, и рушатся именно
  на многоходовых сценариях;
- **устойчивость:** один прогон на задачу, разброса нет. Малые модели шумные;
- **эталон Клода** вписан в стенд константами и прогоном не получен: задачи
  писал он же. Смещение названо, а не спрятано.

## §6. Порядок работы

```bash
ollama create base-local -f Modelfile        # собрать свою конфигурацию
python3 bench.py --selftest                  # канарейка грейдеров
python3 bench.py --model base-local          # прогон
python3 bench.py --model gemma4:e2b
python3 bench.py --show                      # свод с эталоном Клода
```

🔴 **Цена прогона на этой машине.** 8 ГБ памяти распаяны, модель 3–4,6 ГБ лежит
в памяти целиком, своп уже занят — каждый прогон это запись на SSD, у которого
ресурс выработан на 112 % (`12-workstation-kit/HARDWARE.md`). Гонять стенд
в фоне под другой работой нельзя: своп начнёт молотить, и замер будет мерить
не модель, а подкачку.
