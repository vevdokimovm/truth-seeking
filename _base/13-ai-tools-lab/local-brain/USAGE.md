## §1. Какой моделью пользоваться — короткий ответ

**`gemma4:e2b`.** По баллу она равна `base-local` (71 из 100 на задачах этой
системы), но **быстрее впятеро**: 4.8 против 1.0 токена в секунду. На задаче
извлечения `base-local` думала 306 секунд, Gemma — 15.

`base-local` (Qwen3.5 со сводом правил внутри) остаётся как второй номер:
она единственная верно взяла классификацию. Берётся точечно, когда ответ
нужен один и правильный, а ждать три минуты не жалко.

🔴 **Ни одна из двух не годится там, где есть запрет или приватность.**
Обе провалили тест на запрет: `base-local` отказала от внешнего адреса
и следующей строкой предложила две запрещённые команды.

## §2. Запуск: три способа, все из iTerm

Сервер уже работает — приложение Ollama держит его на `127.0.0.1:11434`.
Отдельно запускать ничего не нужно.

### Разговор

```bash
ollama run gemma4:e2b
```

Открывает диалог. Выход — `/bye` или `Ctrl+D`. **`Ctrl+C` прерывает только
текущий ответ**, а не сессию.

### Один вопрос без диалога — то, чем пользуются чаще всего

```bash
ollama run gemma4:e2b "сожми в одно предложение, сохранив все числа: <текст>"
```

### Из конвейера — самое полезное для системы

```bash
cat reports/incidents/PITFALLS.md | head -60 | \
  ollama run gemma4:e2b "выдели тезисы, сохрани все числа и имена файлов"
```

🔴 **Держи ввод коротким.** Чтение промпта идёт со скоростью 2–20 токенов
в секунду: страница текста читается секунды, а свод правил на 20 тысяч
токенов — десятки минут. Это не про качество ответа, это про физику машины.

### Через API, если нужен разбор ответа скриптом

```bash
curl -s http://127.0.0.1:11434/api/generate -d '{
  "model": "gemma4:e2b",
  "prompt": "Ответь одним словом: архитектура или процесс?",
  "stream": false,
  "think": false,
  "options": {"temperature": 0, "num_predict": 64}
}' | python3 -c "import json,sys; print(json.load(sys.stdin)['response'])"
```

🔴 **`"think": false` обязателен.** Gemma 4 — «думающая» модель: без этого
ключа весь бюджет токенов уходит в поле `thinking`, а `response` приходит
**пустым**. Замерено: 64 токена, 80 секунд, ноль полезного вывода.

## §3. Сломает ли это что-нибудь — честно, по пунктам

**Данные никуда не уходят.** Сервер слушает `127.0.0.1` — это петля внутри
машины, наружу трафика нет. Ни один вопрос не покидает ноутбук.

**Что реально расходуется:**

| Ресурс | Цена | Что делать |
|---|---|---|
| **Память** | модель лежит в памяти целиком: 4.6 ГБ у Gemma при 8 ГБ всего | закрыть браузер и IDE перед долгим прогоном |
| **Своп, а через него SSD** | 🔴 главное. Нехватка памяти → запись на диск, а его ресурс выработан на 112 % | не гонять фоном под другой работой |
| **Диск** | Gemma 4.6 ГБ + Qwen 3.4 ГБ (блобы общие), сейчас свободно 29 ГБ | лишние модели удалять |
| **Процессор** | все 4 ядра под нагрузкой, ноутбук греется и шумит | долгие прогоны — с зарядкой |

**Чего НЕ случится:** система не «сломается», файлы не пострадают, настройки
не поменяются. Ollama живёт в своём каталоге и в чужие не лезет. Худшее —
машина начнёт свопить и всё замедлится; лечится закрытием модели.

### Погасить и убрать

```bash
ollama ps                      # что сейчас загружено в память
ollama stop gemma4:e2b         # выгрузить модель, память вернётся
ollama rm qwen3.5:4b           # удалить веса совсем, освободить диск
```

Модель сама выгружается из памяти через 5 минут простоя.

🔴 **Приложение Ollama стартует вместе с системой** и держит сервер
постоянно. Сервер в простое почти ничего не ест (память занимает модель,
а не он), но если нужна тишина — выйти из приложения через значок в строке
меню.

## §4. Как этим пользоваться правильно — в одну строку

**Узкий шаг с проверяемым выходом.** Не «разберись с репой», а «выдели числа
из этого абзаца», «отнеси к одному из четырёх классов», «напиши строку
коммита». Выход проверяет гейт или ты сам за пять секунд.

Замер это подтверждает: модели взяли сжатие, извлечение, классификацию
и формат коммита — и провалились на всём, где нужно держать правило
или вести цепочку.

🔴 **Где НЕ применять:** решение «дубликат ли это» · что поднять в свод
правил · что угодно с запретами · длинный контекст · цепочки действий.
Там её ошибку никто не поймает, а это единственное, что делает слабую
модель опасной.

## §6. 🔴 Может ли локальная модель сломать систему — разбор по механике

**Сама по себе — нет, и это не успокоение, а устройство.** Ollama — генератор
текста за HTTP на петле. У него **нет доступа к файлам, нет возможности
запустить команду, нет прав на репозитории**. Он получает строку и возвращает
строку. Всё.

Опасность появляется ровно в трёх местах, и все три — снаружи модели:

| Где риск | Что именно | Чем закрыт |
|---|---|---|
| **ты исполняешь её вывод** | скопировал предложенную команду в терминал | 🔴 ничем, кроме твоих глаз. Замер: обе локальные предложили запрещённые команды, одна выбрала «откатить чужие правки» |
| **скрипт пишет её вывод в файлы** | автоматическая разметка, сжатие в тезисы | гейты: `revision_check`, `naming_check`, `links_check`, `journal_audit` |
| **расход железа** | своп → запись на SSD с износом 112 % | `hw_series.py`: ряд покажет скачок записи |

🔴 **Главное правило, выведенное из замера, а не из осторожности:**
**вывод локальной модели никогда не исполняется и никогда не попадает в базу
без проверки.** Не потому что она глупая, а потому что она ошибается **молча**:
в трудном наборе `base-local` выдала 956 473 ГБ/сутки там, где верно 1232 —
промах в 776 раз, поданный уверенно и без оговорок.

### Восстановимо ли, если всё же напортила

**Почти всё — да, одной командой.**

```bash
git -C ~/repos/<репа> diff                 # что изменилось в дереве
git -C ~/repos/<репа> checkout -- <файл>   # откатить один файл
git -C ~/repos/<репа> checkout .           # откатить всё незакоммиченное
```

Плюс релизы: у каждой версии на GitHub лежит архив всего дерева, сверенный
по sha256 — то есть любое состояние восстанавливается целиком.

🔴 **Что восстановимо ПЛОХО — и это надо знать заранее:**

1. **Незакоммиченная работа.** `git checkout` вернёт файл к последнему коммиту
   и снесёт всё, что не закоммичено, — в том числе твоё. Поэтому перед любым
   автоматическим прогоном: `git add -A && git commit` или хотя бы `git stash`.
2. **Замороженные документы.** Правило «история не переписывается» есть,
   а исполнителя у него нет: `links_check` замороженную зону **пропускает**
   (71 документ), проверки целостности не существует. Тихая правка старого
   отчёта — единственное, что система сегодня не заметит. Это открытая зона
   в паспорте (`113` §5), и до её закрытия автоматическую правку замороженных
   документов не запускать вовсе.
3. **Числа в прозе.** Подменённое число выглядит как текст и проходит любой
   формальный гейт. Ловит только сверка с диском — там, где она заведена.

### Как проверить после работы с моделью — четыре команды

```bash
git -C ~/repos/base-repo status --short          # что вообще изменилось
python3 scripts/revision_check.py                # 45 проверок, включая числа в прозе
python3 scripts/repo_invariants.py --all --quiet-ok
python3 12-workstation-kit/bin/hw_series.py --show   # не скакнула ли запись на SSD
```

Если гейт зелёный, а `git diff` показывает только то, что ты просил, — работа
чистая. 🔴 Зелёный гейт при непонятном `diff` — это не «всё хорошо», это
«гейт этого не видит».

## §7. Как сделать локальную модель лучше — пять путей по отдаче на усилие

| Путь | Что даёт | Цена |
|---|---|---|
| **1. Архитектура вместо размера** | на CPU решает не число параметров, а сколько их активно на токен. MoE-модели (малая доля активных весов) дают кратно больше токенов в секунду при том же объёме | время на подбор, гигабайты диска |
| **2. Узкий промпт вместо длинного** | чтение промпта идёт 2–20 ток/с: каждая лишняя тысяча токенов — это минута до ответа. Короткий системный промпт и `num_ctx` под задачу | ничего, только дисциплина |
| **3. `Modelfile` под конкретную задачу** | не одна «универсальная» модель, а несколько сборок: под разметку, под сжатие, под коммиты. У каждой свой промпт и температура | по 5 минут на сборку, диск не тратится (база общая) |
| **4. Дообучение LoRA на своих данных** | модель начнёт писать в конвенциях базы и знать её структуру. 🔴 **Мышление не улучшится** — LoRA учит стилю и формату | нужен GPU: на этой машине невозможно, только бесплатный Colab/Kaggle, часы работы |
| **5. Поиск вместо памяти** | не заставлять модель помнить базу, а подавать ей нужный фрагмент: индекс по 70 репам + короткий промпт. Снимает и длинный контекст, и выдумки | день работы, зато закрывает главную слабость |

🔴 **Путь 5 — лучший по отдаче, и он не про модель.** Слабая модель плоха
памятью и хороша переформулированием. Значит её не надо спрашивать «сколько
карточек в реестре» — надо дать ей строки из реестра и спросить «сведи».
Обе локальные это подтвердили: на вопрос без источника обе честно сказали
«не знаю» и попросили фрагмент.
