# incidents/ — полные разборы инцидентов (post-mortem)

Здесь лежат **полные post-mortem'ы** — файлы-разборы инцидентов (реальная поломка/дефект и/или
влияние). Формат — `../incident-postmortem-guide.md`. Сводки-строки по каждому — в реестре
`../incidents-summary.md`. Карточки дефектов — по `../bug-report-template.md`.

Имя файла: `<тема>_incident.md` или `<тема>_incident_postmortem.md` (английский snake_case).

Автогенерация: реальная поломка/дефект → разбор сюда + строка в реестр, без отдельной просьбы
(`../../00-infrastructure/20-knowledge-capture-protocol.md`).

> **Что здесь лежит в самой base-repo:** инциденты про **систему** — деплойер, гейты, режимы
> разрешений, git-механика. Инциденты про содержание конкретной репы остаются в ней.
> Граница и порядок повышения — `../README.md`.

**Не переименованы намеренно.** Имя файла — адрес: переименование обрывает
ссылки, которые могли остаться в чужих репах и в истории. Правило именования
действует для новых разборов, старые остаются под своими именами и находятся
через этот навигатор — так дешевле и не теряется история.

Второй, к тому же, **не инцидент системы**: `starship` — оболочка владельца,
а не деплойер и не гейт. По границе выше ему место в `12-workstation-kit`;
перенос отложен по той же причине — адрес дороже опрятности.
