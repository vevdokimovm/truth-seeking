**Сетевая диагностика (для понимания VPN):**
- Happ Plus (VLESS TCP Reality, выход Швеция), режим **системного прокси** (не TUN).
- Локальные прокси-порты: **10808** и **10820** — оба работают и как HTTP, и как SOCKS5 (тест дал 200 на archive.org).
- `ping 1.1.1.1` и `nslookup` — **таймаут**: ICMP и UDP:53 не проходят через TCP-only туннель. TUN не включён.
- Из-за этого CLI-инструменты со своим DNS падают, если не гнать их через прокси (`--all-proxy=http://127.0.0.1:10808`), тогда DNS резолвит шведская сторона.

## 4. Точный диагноз блокера (одним абзацем)

Единственный полный первоисточник — justice.gov — закрыт **Akamai Bot Manager**, который отдаёт `403` любому автоматизированному клиенту (обычный curl, curl_cffi-Chrome — оба), **независимо от IP** (проверено: шведский датацентровый и жилой российский — оба 403). Реальный браузер проходит, потому что исполняет JS-сенсор Akamai и получает куку `_abck`/`bm_sv`. Массовые ZIP-архивы DOJ убрал ~6 фев 2026 (осталась выдача по одному PDF, но и она за Akamai). Все известные HTTP-зеркала мертвы или неполны: GeekenDev-бакет снесён; archive.org держит только фрагментарные пере-OCR-загрузки, не чистые 12 зипов. Значит любой чисто-скриптовый подход к justice.gov в лоб обречён — нужна **реальная браузерная сессия** (её кука или headless-Chrome), либо **торрент** (Василий пока против), либо **найти полный archive.org-мирор** (не найден).

## 5. Гипотезы и неиспробованные опции (ранжировано на будущее)

1. **🟢 Browser-cookie → aria2 (консольный, без торрента — прямо под предпочтение Василия).** Открыть justice.gov в браузере (проходит Akamai, ставит куки), экспортировать `cookies.txt` (расширение Get cookies.txt / Safari Web Inspector), скормить `aria2c --load-cookies=cookies.txt` или `curl -b`. Дальше итерировать: краулер листингов (тоже с кукой) → URL всех PDF → пачечная скачка. **Риск:** кука `_abck` имеет состояние валидности и может протухать/ре-челленджиться на объёме → возможно, придётся периодически обновлять куку из браузера или добавлять задержки. Проверить это — задача №1 следующей вахты.
2. **🟢 Playwright + настоящий Chromium.** Реальный Chrome проходит Akamai нативно. Скриптом гонять и краулинг листингов, и скачку PDF (либо забирать куки и отдавать aria2). Больше сетапа (`pip install playwright && playwright install chromium`), но самый устойчивый. Хорош тем, что переживает ре-челлендж.
3. **🟡 Найти ПОЛНЫЙ archive.org-мирор (не фрагментарный).** IA заявляет 1 366 140 заархивированных PDF — где-то есть большой айтем/коллекция. Копать через `ia` CLI (`pip install internetarchive`), метадату-API (`archive.org/metadata/<id>`), поиск по загрузчику. Если найдётся чистый per-dataset айтем — качать по HTTP через прокси, без Akamai вообще. Чисто и быстро, если существует.
4. **🟡 Торрент (Василий против, но это канонический способ раздачи).** qBittorrent уже стоит. Через TCP: Настройки→Соединение→Прокси **SOCKS5 127.0.0.1:10808** + «для пиров», выключить DHT/PeX/LSD (UDP), добавить **HTTP/HTTPS-трекеры** к торренту (udp-трекеры не пройдут). Либо включить **TUN с UDP-релеем** в Happ/sing-box — тогда DHT работает штатно. Держать как последний резерв.
5. **🔴 Смена VPN-выхода / жилой прокси.** Тест №9 показал: жилой РФ-IP тоже 403 → **IP не решает**, Akamai режет клиента. Понижаем приоритет; residential-прокси поможет только если совместить с браузерным фингерпринтом (т.е. всё равно нужен путь 1/2).

**Что точно НЕ делать:** долбить новые HTTP-зеркала по одному (каждое либо за бот-фильтром, либо мёртвое) и крутить `impersonate`-профили curl_cffi (Akamai их знает).

## 6. Конкретный план на следующую вахту (по шагам, начинать отсюда)

**Ветка A — сначала пробуем самый дешёвый путь (browser-cookie):**
1. Открыть в браузере (где работает VPN) страницу листинга: `https://www.justice.gov/epstein/doj-disclosures/data-set-1-files` — убедиться, что грузится (Akamai пройден человеком).
2. Поставить расширение экспорта кук (Chrome: «Get cookies.txt LOCALLY»; Safari: Web Inspector → Storage → Cookies, или расширение). Экспортнуть куки для `justice.gov` в `~/epstein/cookies.txt` (формат Netscape).
3. Тест одной PDF-ки с кукой (подставить реальное имя файла — взять со страницы листинга):
   ```bash
   aria2c --load-cookies=cookies.txt --all-proxy="http://127.0.0.1:10808" \
     -d test "https://www.justice.gov/epstein/files/DataSet%201/<ИМЯ>.pdf"
   ```
   - Скачался PDF (не 403, не HTML) → **путь открыт**. Дальше: краулер листингов с той же кукой соберёт все URL, aria2 скачает пачкой. Обновлять куку из браузера при появлении 403.
   - Снова 403 → кука не проходит для файловых эндпоинтов или протухла → ветка B.
4. Если пошло — модифицировать `efta_manifest.py`: добавить `--load-cookies` в curl_cffi-сессию (или гнать через локальный прокси + куки) и собрать полный манифест листингов, затем скачать по нему.

**Ветка B — если куки не хватило (Playwright):**
1. `cd ~/epstein && source .venv/bin/activate && pip install playwright && playwright install chromium`
2. Скрипт на Playwright: открыть каждую страницу листинга датасета (реальный Chromium проходит Akamai), выпарсить ссылки на PDF, скачать их через `page.context.request` (в той же прошедшей челлендж сессии) или экспортировать `storage_state`/куки и отдать aria2.
3. Прогресс писать в `~/epstein/PROGRESS.md`.
*(Скрипт Playwright напишу на следующей вахте под конкретную структуру страниц — 5 минут.)*

**Ветка C — параллельно проверить полный archive.org:**
```bash
pip install internetarchive
ia search 'epstein DOJ dataset' --itemlist
# по найденным id:  ia metadata <id> ;  ia download <id> --format ZIP
```
Если найдётся чистый айтем на 12 датасетов — это может обогнать A/B.

**После получения файлов (любой веткой) — конвейер уже готов (файл 10):**
```bash
# распаковка (если zip) или просто папка PDF
python efta_index.py build --corpus ./corpus --db efta.db   # индекс
python efta_index.py stats --db efta.db                     # прислать в чат
# OCR фоном для сканов:
find corpus -name '*.pdf' | parallel -j 8 'ocrmypdf --skip-text --optimize 0 {} {} 2>>ocr.log || echo "FAIL {}">>ocr.log'
```
Затем NER-имена (файл 08 §9) и батч-разбор со мной.

## 8. Открытые вопросы и риски (держать в голове)

- **Валидность куки `_abck`** на объёме тысяч запросов — главный неизвестный фактор ветки A.
- **DS9 неполон у самого источника** (~49 из 180 ГБ обрывался; реконструкция ~99,5%, но ~23 файла и ~10 ГБ видео DOJ, похоже, не выкладывал никогда). «Скачать всё до байта» невозможно в принципе (плюс DOJ удержал ~2,5 млн стр. — файл 05).
- **Расхождение хэшей источников** (файл 11 §4): у части датасетов SHA256 разных источников не совпадают («updated torrent contains less redactions») — при верификации сверять с хэшем ТОГО источника, откуда качал; less-redacted версии — отдельная интересная зона для анализа редактур.
- **Этика неизменна** (файл 07 §6): имена жертв не деанонимизируем; утечки ПДн не распространяем (канал жалоб DOJ: EFTA@usdoj.gov); CSAM — ни при каких; tip-слой считаем непроверенным до верификации.
- **Отдельно от корпуса** библиотека `00–11` уже даёт ответ на исходный запрос Василия (имена, контексты, аудит вирусных тезисов) — если силы не вернутся на скачку скоро, это самостоятельный результат.
